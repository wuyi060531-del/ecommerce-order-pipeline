# CSV 展示导出的边界

2026-11-14：修复通过订单号、用户编号、商品或城市进入 CSV 的公式前缀。

所有导出模式（check、run、analyze）共用一个序列化边界。对以公式字符
`= + - @`（含全角形式）开头、或去掉前导空白/控制字符/BOM 后以这些字符
开头的字符串，在导出副本前加可见的 `text:`。以制表、回车或换行开头的
字符串也处理。CSV 字段统一加引号并转义内嵌引号，防止逗号或换行拆出新单元格。
数值类型不加前缀，正常文本也不改变。

例如源商品名 `=1+1` 的 CSV 单元格内容是 `text:=1+1`。采用可见文字标记，
不依赖表格软件是否保留单引号或制表符。此标记属于展示格式，不是业务数据清洗。
输入 CSV、内存中的订单/问题、数据库业务值及 raw_record JSON 均不做此改写。
金额计算、订单唯一键、批次身份和 SQL 聚合不变。report.md 展示的是这些 CSV 的值。

CSV 是供人查看的展示产物，不承诺无损重新导入；不要自动去掉 text: 后再用表格
打开。精确数据应从受控输入、数据库及审计 JSON 获取。此功能不修复旧导出，
须重新执行 ETL/分析；只执行 report 命令不会重新导出 CSV。manifest 会记录实际
新产物哈希。未验证各版本 Excel/LibreOffice，不能承诺任意转换或用户编辑后的安全。

背景：[OWASP CSV Injection](https://owasp.org/www-community/attacks/CSV_Injection)。
CSV 本身没有可信的单元格类型；仅加引号并不能阻止公式。防护不执行测试字符串，
回归测试用 CSV 解析器核对每个单元格，并验证原始数据与数据库不变。
